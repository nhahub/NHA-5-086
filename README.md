# Olist E-Commerce Data Cleaning & Engineering

A hands-on Data Engineering project focused on exploring, cleaning, validating, and preparing the Olist Brazilian E-Commerce dataset using Python, Pandas, and MySQL.

The project follows a structured workflow to transform raw CSV files into clean, validated datasets and prepare them for relational database storage and SQL analysis.

## Project Objectives

- Explore and understand real-world e-commerce data.
- Perform data profiling and quality checks using Pandas.
- Handle missing values, duplicates, inconsistent data types, and invalid records.
- Validate dataset identifiers and relationships.
- Prepare clean datasets for loading into MySQL.
- Design relational tables using primary keys and foreign keys.
- Practice a reproducible and organized data processing workflow.

## Dataset

This project uses the **Brazilian E-Commerce Public Dataset by Olist**, which contains information about customers, sellers, products, orders, payments, reviews, and geolocation.

The project works with nine CSV files:

| Dataset | Description |
|---|---|
| `olist_customers_dataset.csv` | Customer identifiers and location information |
| `olist_geolocation_dataset.csv` | ZIP codes and geographical coordinates |
| `olist_products_dataset.csv` | Product attributes and category information |
| `olist_sellers_dataset.csv` | Seller identifiers and location information |
| `product_category_name_translation.csv` | Product category name translations |
| `olist_orders_dataset.csv` | Order details and timestamps |
| `olist_order_items_dataset.csv` | Products and sellers associated with orders |
| `olist_order_payments_dataset.csv` | Order payment information |
| `olist_order_reviews_dataset.csv` | Customer reviews and ratings |

**Dataset source:** Search for *Brazilian E-Commerce Public Dataset by Olist* on [Kaggle](https://www.kaggle.com/).

After downloading the dataset, place the original CSV files inside `data/raw/`.

## Notebook Workflow

### 1. Customers & Geolocation

**Notebook:** `01_customers_geolocation.ipynb`

Files:
- `olist_customers_dataset.csv`
- `olist_geolocation_dataset.csv`

Planned tasks:
- Inspect dataset dimensions, columns, data types, and missing values.
- Identify duplicate records and validate customer identifiers.

Files:

**Notebook:** `03_orders_transactions.ipynb`

- `olist_orders_dataset.csv`

- `olist_order_reviews_dataset.csv`

Planned tasks:
- Inspect order and transaction data.
- Validate date and numeric columns.

- Save cleaned datasets to `data/processed/`.

## Data Processing Workflow

The project follows this planned workflow:

```text
Raw CSV Files
     |
     v
Data Profiling & Exploration
     |
     v
Data Cleaning & Transformation
     |
     v
Data Quality Validation
     |
     v
Processed Datasets
     |
     v
MySQL Table Design
     |
     v
Data Loading & Relational Constraints
     |
     v
SQL Validation & Analysis
```

Each CSV file is initially loaded into its own Pandas DataFrame.

The cleaning process may include:

- Missing-value analysis and appropriate handling.
- Duplicate detection and removal when justified.
- Column name standardization.
- Data type correction.
- Date and numeric conversion.
- Text cleaning and consistency checks.
- Identifier validation.
- Data quality checks before saving processed files.

Cleaning decisions will depend on the meaning of each column and the structure of the source data.

### DataFrame Operations

The project will use appropriate Pandas operations based on the task:

- `concat()` to combine compatible datasets vertically.
- `merge()` to join datasets using appropriate keys.
- `groupby()` for aggregation and summary analysis.
- `to_datetime()` and `to_numeric()` for data type conversion.

Joins will be validated where appropriate to detect unexpected row multiplication and unmatched records.

## MySQL Integration

After cleaning and validating the datasets, the next stage is to prepare a relational schema in MySQL.

The planned database work includes:

- Creating appropriate tables for the cleaned datasets.
- Defining primary keys.
- Establishing foreign key relationships where valid.
- Loading data in an order that respects relational constraints.
- Running SQL queries to validate record counts and referential integrity.

The final schema and constraints will be determined after inspecting the actual data and validating the relationships between datasets.

Python database integration will use SQLAlchemy and PyMySQL.

## Installation & Setup

### Prerequisites

- Python compatible with the selected project dependencies.
- Git.
- uv.
- MySQL Server and a MySQL client, such as MySQL Workbench, for the database stage.

### 1. Clone the Repository

```bash
git clone https://github.com/YOUR_USERNAME/olist-data-engineering.git
cd olist-data-engineering
```

Replace `YOUR_USERNAME` with your GitHub username.

### 2. Install Dependencies

If the repository contains `pyproject.toml` and `uv.lock`, run:

```bash
uv sync
```

To create a new environment and install the project's initial dependencies when setting it up from scratch:

```bash
uv init
uv add pandas numpy jupyter ipykernel sqlalchemy pymysql matplotlib seaborn
```

Use the appropriate setup path rather than initializing an existing project again.

### 3. Add the Dataset

Download the Olist dataset from Kaggle and place the nine CSV files in:

```text
data/raw/
```

Keep the original files unchanged.

### 4. Launch Jupyter Notebook

```bash
uv run jupyter notebook
```

Open the notebooks in the `notebooks/` directory.

In VS Code, select the Python interpreter associated with the project's `.venv` environment.
